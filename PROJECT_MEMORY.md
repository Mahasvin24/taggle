# Project Memory

## Decisions

- **Two-player scenarios** — Each round assigns a neutral everyday scene to guide the writer (gas station, shopping, delivery, etc.). Keep it stable through setup, writing, guessing, and reloads; avoid suggesting an emotion in the prompt. Its title is stored using the synthetic pair's existing `category` field. Don't retroactively attach a random scene to an already written or pending legacy review. Evidence: `frontend/games/wavelength/scenarios.ts`, `game.tsx`.
- **Semicircle visualization** — User prefers the semicircular form for Common Ground. Preserve the emotion shuffle, segmented semicircular arc, animated needle sweep/landing, and prominent percentage; do not replace it with a full circular wheel. Evidence: `frontend/games/wavelength/emotion-wheel.tsx`.
- **Common Ground sentiment POC** — The Wavelength-inspired game lives at `/games/wavelength` with solo review rating and same-device two-player review writing/guessing. The two loops intentionally produce different data: human interpretations of authored demo texts versus synthetic texts with separate writer intent and reader interpretation. Preserve that separation. Research, sources, scoring incentives, and the proposed validation pilot are canonical in `research/wavelength/README.md`.
- **Emotion-first rounds** — User requested familiar emotion pairs and visible spin/select sequences rather than reading a graph. Each round shuffles satisfaction, anger, happiness, or excitement; two-player setup then spins a wheel to a secret percentage. Solo reference spins happen only after saving the guess. Keep `axis_id` in submissions/exports and use separately authored references per dimension; never relabel satisfaction scores as anger. Existing DB rows migrate to satisfaction and legacy pending retries remain valid. Evidence: `frontend/games/wavelength/round-setup.tsx`, `emotion-wheel.tsx`, and backend migration tests. Last verified: 2026-10-24.

## Constraints and invariants

- **Sentiment references and repeats** — The 24 seed reviews and reference scores are authored demonstrations, not real customers, crowd consensus, or gold labels. Solo references are returned only after a saved rating; low game points never invalidate a judgment. The browser avoids previously submitted reviews, and the API retains repeat ratings with `first_exposure=false` / `feedback_conditioned=true`, keyed to a stable anonymous browser ID. IDs do not establish distinct people. Evidence: `backend/app/games/wavelength/router.py`, `frontend/games/wavelength/game.tsx`.
- **Sentiment storage and handoff** — `backend/wavelength.db` (override `WAVELENGTH_DB_PATH`) stores raw ratings separately from synthetic pairs and preserves reference versions. Retries must reuse the original submission ID and immutable payload. Pass-and-play hides the target from the rendered guessing UI, but browser storage contains game state; it is a casual handoff, not a secure network room. Local dataset views/exports have no authentication. Evidence: `backend/tests/test_wavelength.py`, `research/wavelength/playtest.py`.
- **Fruit Ninja rule** — Players slash rotten fruit and collect healthy/fresh fruit. Preserve this mapping when building gameplay; it is easy to accidentally invert it because of the original Fruit Ninja convention. Evidence: `research/fruit-ninja/dataset-review/manifest.json` (`state` and `action`).
- **Cutout label inheritance** — Every segmented fruit inherits its source photo's exact fresh/rotten label, fruit type, and game action, including individual fruit taken from a group. Do not reclassify individual cutouts silently. Evidence: `research/fruit-ninja/dataset-review/segmentation-manifest.json`, `segment-labels.csv`, and `test_segmentation.py`.
- **Fruit Shift** — The implemented plan and operational rules are in `backend/app/games/fruit_ninja/README.md`. Use 183 backend-owned sprites, 91 frozen reference controls and 92 independently labeled targets. SQLite is `backend/data.db`; do not replace it with Postgres or infer player labels from historical source conditions.
- **Fruit game direction** — Keep this a playful prototype: minimal HUD, a flat light ground for photographic fruit, and no packing-line/work dashboard framing. The manual is one scene of five healthy and five rotten strawberries from the frozen control set, including subtle examples. Multi-slice effects are cosmetic; perfect combos use grouped accuracy and reward healthy passes as well as rotten cuts. Do not add per-fruit correctness hints or slice-only point incentives. Canonical mechanics: `backend/app/games/fruit_ninja/README.md`; implementation: `frontend/games/fruit-ninja/arena.tsx` and `game.tsx`. Last verified: 2026-10-24.

## Discoveries and gotchas

- **Fruit label-quality pilot** — The reproducible gradient-boosted experiment and report are in `research/fruit-ninja/label-quality/`. Freeze the snapshot and group train/test by source-photo SHA-256; never randomly split sibling cutouts, use historical target labels as gameplay truth, or treat repeated local profiles as independent annotators. Recorded pilot: 80 eligible votes → 68 non-tied training cutouts; gameplay model 55.3% photo-balanced reference accuracy (conditional photo-bootstrap interval 39.0–71.5%), versus 50% constant baseline. This does not establish reliable label quality or a causal effect of UI changes. Source-label disagreements are audit candidates, not automatic corrections; obtain blind cutout adjudication and a new untouched photo holdout before stronger claims. The matched-image 70/30 follow-up is in `results_mix/REPORT.md`: 82.4% mixed vs 79.5% normal photo-balanced accuracy, but lower ordinary accuracy/rotten recall and a paired interval crossing zero; no clear overall winner. Evidence: `results/REPORT.md`, `results_mix/REPORT.md`, saved folds and experiment tests. Last verified: 2026-10-24.

- **QA data separation** — The browser playthrough’s 106 test events are preserved in Git-ignored `backend/fruit-shift-browser-qa.db`, separate from production `backend/data.db`. Do not mix deterministic QA judgments into the usable labeling dataset. Verification: `research/fruit-ninja/game-verification/README.md`.

- **Fruit imagery** — The preferred dataset candidate is Sultana et al.'s Fresh and Rotten Fruits (Mendeley DOI `10.17632/bdd69gyhv8.1`, published CC BY 4.0). A fixed 48-image sample and visual assessment are in `research/fruit-ninja/dataset-review/README.md`. The Project-AgML mirror's `raw` configuration provides original photos without downloading the complete archive. Use raw photos when selecting sprites; the augmented set does not add independent fruit examples. Last verified: 2026-10-24.
- **Segmentation trial** — All 48 sampled sources now have model-assisted, visually selected instance masks and 236 transparent fruit-cutout candidates. The gallery shows each source's cutouts and numbered overlay. The user selected the 183 kept cutouts for the Fruit Shift prototype. Source labels remain provenance, with only the fixed reviewed reference subset used for quality checks; target labels come from gameplay. Canonical results and rerun instructions: `research/fruit-ninja/dataset-review/README.md` and `segmentation-manifest.json`. The selected proposal indices depend on cached ordering, so review regenerated proposals before reusing selections on another device/version. Last verified: 2026-10-24.
- **Partial-fruit selection** — The geometric filter plus documented visual decisions keeps 183 candidates and excludes 53 heavy partials. Every source retains its complete `instances` inventory and inherited labels; check `quality.decision` before counting or using a crop. `segment-labels.csv` is kept-only; `segment-review.csv` contains all candidates and reasons. Excluded PNGs are intentionally preserved for inspection. Filtering can be rerun from canonical source masks without model inference; thresholds, visual decisions, and instructions are in the dataset-review folder. Last verified: 2026-10-24.
